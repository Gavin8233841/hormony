## 一、设计哲学

### 1.1 核心原则

基于 HarmonyOS Design 的 "One Harmonious Universe" 理念 [P2-社区转述] 与竞品分析提炼：

| 原则 | 含义 | 参考来源 |
|------|------|----------|
| **用户语言** | 界面文案用学生能懂的话，不暴露技术架构术语 | Codex 指令 + 得到 App 文案风格 |
| **内容优先** | 弱化装饰，强化内容本身 | 知乎回答展示（弱化来源、突出内容）|
| **轻量反馈** | 每个操作都有即时视觉反馈，但不喧宾夺主 | HarmonyOS Design 轻拟物美学 |
| **学习闭环** | 学→练→问→评 形成完整循环 | 夸克学习"学练评"闭环 + 得到学习闭环 |
| **渐进激励** | 学习行为量化 → 可见进度 → 成就感 | 学习强国积分体系 + Flomo 热力图 |

### 1.2 与竞品的差异化定位

```
        高 AI 能力
            │
    夸克学习  │  鸿学伴（目标位置）
   (拍照搜题) │  (AI 助教 + 知识管理 + 学习计划)
            │
 ───────────┼──────────── 高知识管理
            │
    百词斩   │  Flomo
   (游戏化)  │  (碎片笔记)
            │
        低 AI 能力
```

**我们的差异化**: AI 助教（多 Agent 协作）+ 课程知识库（RAG 引用）+ 学习计划自动拆解，三者形成闭环——这是单一竞品未覆盖的组合。

## 二、视觉设计系统

### 2.1 色彩体系

> ✅ 本文档数值已经过 P0 级官方文档核实（2026-06-27）。社区转述的 `#007DFF`/`8vp`/`500ms` 均已被官方文档否定，详见第九节核实结果。

#### 主色

| 色彩 | 色值 | 用途 | 来源 |
|------|------|------|------|
| 宇宙蓝(brand) | `#0a59f7` | 官方品牌色、主操作色、标题强调、主按钮 | [P0-官方] 色彩 Token brand=#ff0a59f7 |
| ~~系统蓝~~ | ~~`#007DFF`~~ | ~~社区误传为系统蓝~~ | **[P0-已否定]** 仅是 TextInput 光标默认色，非品牌色 |

#### 功能色

| 色彩 | 色值 | 用途 |
|------|------|------|
| 成功绿 | `#4caf50` | 进度条、正确率、已掌握 |
| 警告橙 | `#ff9800` | 学习天数、待办提醒 |
| 错误红 | `#e53935` | 加载失败、薄弱知识点 |
| 紫色 | `#9c27b0` | 课程分类标识 |
| 青色 | `#00bcd4` | 学习画像标识 |

#### 中性色

| 色彩 | 色值 | 用途 |
|------|------|------|
| 背景灰 | `#f5f6f8` | 页面背景（浅色主题）|
| 卡片白 | `#ffffff` | 卡片、输入框背景 |
| 主文字 | `#1a1a1a` | 标题、正文 |
| 次文字 | `#929292` | 副标题、描述文字 |
| 辅助灰 | `#cccccc` | 箭头、占位符 |

#### 设计依据

- HarmonyOS Design "色调柔和协调，含科技感蓝色调" [P2-社区转述]
- 学习强国品牌红太严肃，得到偏商务灰——学习助手适合温和蓝绿系
- 百词斩/Flomo 均采用浅色背景 + 白色卡片，降低长时间学习视觉疲劳

### 2.2 字体规范

| 场景 | 字号 | 字重 | 字色 | 行高参考 |
|------|------|------|------|----------|

> HarmonyOS Sans 为无衬线字体，**9 种字重**（Thin/UltraLight/Light/Regular/Medium/SemiBold/Bold/Heavy/Black），免费商用，针对多设备屏幕优化 [P0-官方 鸿蒙黑体文档]
> ArkUI `fontWeight` 默认值 500（Medium），number 类型取值 [100, 900] 间隔 100 [P0-官方 Button 文档]

### 2.3 间距与圆角

| 元素 | 圆角 | 来源 |
|------|------|------|
| 卡片 | 12vp | Index.ets 改版已采用 |
| 按钮/输入框 | 12vp | 统一 |

### 2.4 阴影与层级

HarmonyOS Design 采用 "轻拟物美学" [P2-社区转述]，建议：

| 层级 | 阴影 | 使用场景 |
|------|------|----------|
| 背景层 | 无 | 页面背景 |
| 内容层 | 无阴影，用白色卡片 + 圆角区分 | 卡片、列表项 |
| 浮层 | 轻微阴影 `box-shadow: 0 2vp 8vp rgba(0,0,0,0.08)` | 弹窗、浮动按钮 |

> 当前 Index.ets 改版未使用阴影，仅靠白色卡片 + `#f5f6f8` 背景区分层级——这是正确的轻拟物做法。

## 三、信息架构与导航模式

### 3.1 当前架构

```
Index（首页）
├── Chat（AI 对话辅导）
├── Plan（学习计划）
├── Knowledge（知识库搜索）
├── Course（我的课程）
└── Profile（学习画像）
```

**导航方式**: `router.pushUrl` / `router.back`（已废弃，待迁移 Navigation）

### 3.2 竞品导航模式对比

| 竞品 | 导航结构 | 可借鉴点 |
|------|----------|----------|
| 得到 | 底栏 5 Tab（发现/今日学习/知识账本/已购/我的）| 学习数据独立 Tab |
| 学习强国 | 可定制频道导航 + 内容流 | 频道可编辑拖拽 |
| 知乎 | 底栏 5 Tab（首页/想法/+/通知/我的）| 中间突出创建按钮 |
| Flomo | 无底栏，首页即输入 + 时间流 | 极简，首页零负担 |

### 3.3 建议架构（当前阶段保持 router，未来迁移 Navigation）

**当前阶段（不改架构，只改视觉）**:
```
Index（首页 — 仪表盘式入口）
  → 5 个功能页（平级，各自独立返回）
```

**未来阶段（迁移 Navigation 后可考虑）**:
```
Navigation（根容器）
├── 首页 Tab
│   └── NavDestination: 仪表盘
├── 学习 Tab
│   ├── NavDestination: 课程列表
│   └── NavDestination: 课程详情
├── AI Tab
│   └── NavDestination: 对话
└── 我的 Tab
    └── NavDestination: 画像
```

> ⚠️ Navigation 迁移是 Codex 的架构决策，本框架仅提供参考方案，不在当前阶段执行。

### 3.4 页面间传参

当前方式: `router.pushUrl({ url: 'pages/X' })` 无传参
未来方式: `router.pushUrl({ url: 'pages/X', params: { courseId: 'cs101' } })` 或 Navigation 的 NavPathStack

**Knowledge.ets 已知问题**: 请求体缺少 `courseId` 字段，需在第二批修复。

## 六、技术架构与代码规范

### 6.1 状态管理最佳实践

> 来源: 华为官方《状态管理优秀实践》[P0-官方文档]

| 场景 | 推荐 | 避免 |
|------|------|------|
| 组件内状态 | `@State`（必须初始化）| — |
| 父传子、子不改值 | `@ObjectLink`（不深拷贝）| `@Prop` 会深拷贝，有性能开销 |
| 父子双向同步 | `@Link` | — |
| 跨层级传递 | `@Provide` / `@Consume` | — |
| 状态变量关联组件数 | **< 20 个** | 同一状态绑多个同级组件会同步刷新 |
| 复杂对象 | 拆分对象，控制关联范围 | 对象某属性变化刷新所有关联组件 |
| 循环内读状态 | 循环外读一次存临时变量 | for/while 内频繁读状态变量 |
| 状态变量赋值 | 临时变量算完再一次性赋值 | 直接多次操作状态变量 |

### 6.2 组件封装模式

| 场景 | 推荐方式 | 原因 |
|------|----------|------|
| 纯展示片段（无状态）| `@Builder` | 减少嵌套与节点创建开销 [P0-官方] |
| 带状态的列表项 | `@Reusable @Component` | 组件复用，aboutToReuse 更新数据 |
| 独立页面 | `@Entry @Component struct` | — |

> **⚠️ Index.ets 调试经验**: @Builder 的事件绑定在某些情况下会失效（已在第一批改版中通过内联组件解决）。如果使用 @Builder，需确保事件参数正确传递。

### 6.3 列表性能优化

> 来源: LazyForEach 性能优化实践 [P2-专业社区]

| 要点 | 规范 |
|------|------|
| 数据源 | 必须实现 `IDataSource` 接口 |
| 唯一键 | 用 `item.id`，**严禁用 index** |
| cachedCount | 屏幕可见项的 1-2 倍 |
| 组件复用 | `@Reusable` + `aboutToReuse` |
| 布局切换 | 慎用 if/else 控制列表项布局，改用 display 或拆分组件 |
| 图片加载 | `Image.syncLoad(true)` + LRUCache |
| 短列表 (<100 项) | 用 `ForEach` 更简单 |
| 长列表 (≥100 项) | 用 `LazyForEach` |

### 6.4 工程分层

> 来源: 官方性能案例库 common_app_development [P0-官方示例]
