# 2026 鸿蒙高校创新赛得分优先实施边界

> 核对日期：2026-06-30。本文以仓库根目录两份官方 PDF 为细则依据，并以官方赛事页确认赛事状态。门户登录后的实时上传字段仍须在正式提交前人工复核。

## 一、权威来源与冲突处理

1. `2026“中国高校计算机大赛―人工智能创意赛”鸿蒙高校创新赛竞赛规程.pdf`：赛程、方向、评分和分阶段材料的主依据。
2. `2026“中国高校计算机大赛―人工智能创意赛”鸿蒙赛道报名手册.pdf`：实际报名入口、文件命名和上传操作的主依据。
3. 官方赛事页：<https://developer.huawei.com/home/C4-AI>。
4. 作品提交入口：<https://developer.huawei.com/consumer/cn/activity/incentive/C4>。

规程写明初赛第 4 项演示材料可选，但报名手册的上传页示例要求作品说明 PDF、演示视频 MP4、Demo ZIP 三份文件。两者存在操作口径差异。项目按更严格口径准备三份材料，并在上传前由队长登录门户核对实时必填项。不得消耗有限的 10 次上传/更新机会做试传。

## 二、方向与时间

- 参赛方向：Agent 创新。
- 初赛截止：2026-07-26 24:00。
- 复赛截止：2026-09-30 24:00。
- 全国总决赛：2026 年 11 月，线下答辩安排以后续通知为准。
- 每一阶段独立评分，前一阶段成绩不带入下一阶段。

Agent 方向强调工作、学习和成长场景中的主动服务、上下文感知和自然交互，可提交 Agent 或 Skills，框架不限。规程中“建议使用三项及以上鸿蒙特性”位于应用创新方向，不写成 Agent 方向的硬性门槛；但作品与鸿蒙无关会被取消资格，因此系统级鸿蒙能力仍是核心展示项。

## 三、评分矩阵与工程映射

| 评分项 | 分值 | 鸿学伴的直接证据 | 当前优先动作 |
|---|---:|---|---|
| 基础创新 | 50 | 画像驱动的计划、学习、检索、测验和再测闭环；可解释 RAG；Agent 主动服务 | 做出服务卡片/通知触达与端云闭环，形成可演示的鸿蒙差异点 |
| 完整度 | 20 | 鸿蒙端完整主流程、错误降级、本地题库与知识库 | 公网 HTTPS 后端、持久化、断网/模型失败降级、提交包实测 |
| 前景评估 | 20 | 真实学习需求、课程扩展结构、低成本部署 | 用用户问题和可量化学习结果说明落地价值，不再单纯扩量数据 |
| 规范性 | 10 | 清晰文档、源码、演示视频 | 按模板与命名交付，维护资源与许可证清单，控制视频在 5 分钟内 |
| 实际应用价值加分 | 20 | 可运行 HAP、完整源码、可访问服务；上架可进一步加分 | 先保证评委能独立运行和访问，之后再评估上架，不以空壳页面替代 |

得分优先顺序：可演示的鸿蒙创新能力 > 端云主流程可靠性 > 正式提交材料 > 更多数据和后台页面。

## 四、提交材料

### 初赛

规程要求：创新点一句话、2 张设计效果图或交互流程图、800 字以内项目介绍；演示材料在规程中为可选。项目按报名手册的严格口径额外准备视频和 Demo ZIP。

### 复赛

创新点、设计图/流程图、项目介绍、源码或测试状态 Agent、5 分钟以内演示视频均为必交。

### 总决赛

在复赛材料基础上补充答辩 PPT 等现场材料。

### 文件规格

- 作品说明：使用官方模板，正文不超过 20 页（参考文献和附录不计），PDF，命名 `01-作品说明文档+参赛队伍名称`。
- 演示视频：MP4，不超过 5 分钟，命名 `02-演示视频+参赛队伍名称`。
- HAP、源码或 Demo：ZIP，命名 `03-作品名称+参赛队伍名称.zip`。
- 报名手册注明整个上传/更新过程最多 10 次。

官方作品说明模板目前未在仓库中找到。队长需从当前门户下载，不能自行猜测模板字段。

## 五、离线与服务器结论

现有规程和报名手册没有“应用必须完全离线运行”的明确要求，也没有要求提交 Web 管理后台。竞赛交付核心是鸿蒙作品、源码和演示材料。

但远程评审不能访问 `localhost` 或模拟器专用的 `10.0.2.2`。最终架构采用双保险：

1. 公网 HTTPS 主服务：提供真实模型、RAG、计划、画像、测验和持久化。
2. 端侧/服务端降级：模型或网络失败时仍能用内置知识与题库完成主要演示，不让流程中断。
3. Web 页面只作为开发、调试和数据观察工具，不投入竞赛前端美化资源。

当前 JSON 持久化只支持单实例。生产目标必须是带持久卷的长驻 Node 容器；无持久文件系统的 Serverless 部署会丢失学习状态，不符合当前架构。

## 六、项目边界

### 立即完成

1. 容器化后端，验证生产构建、健康检查、SSE 和重启后状态保留。
2. 获得公网 HTTPS 地址后替换鸿蒙端提交构建的 `BASE_URL`。
3. 实现一个与 Agent 主动服务直接相关的鸿蒙系统能力，优先服务卡片与学习提醒通知。
4. 整理提交源码清单、第三方资源许可证和密钥排除规则。
5. 下载官方作品说明模板，人工确认门户实时字段和视频必交状态。

### 暂缓

1. Web 管理页面视觉重做。
2. 继续扩大题库、知识切片和外链数量。
3. 为展示技术数量而增加不可见 Agent 或复杂向量数据库。
4. 多用户商业级权限、分布式缓存和多实例部署。

## 七、提交前人工确认项

- 队长、队员、指导教师信息是否完整，复赛报名表签章要求是否满足。
- 门户实际必填文件、单文件大小和文件名是否与手册一致。
- 官方作品说明模板是否为最新版。
- HAP 签名、安装、联网权限和公网域名是否在非开发机环境可用。
- ZIP 中不包含 `.env.local`、API Key、`.runtime`、`node_modules`、构建缓存或个人路径。
