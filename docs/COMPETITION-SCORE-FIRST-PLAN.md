## 三、证据等级与真实性红线

全文只使用以下七种证据等级：

- **源码确认**：只证明源码、配置、文档或数据存在，不证明能够构建或运行。
- **静态诊断通过**：只证明 lint、类型检查或 ArkTS 诊断通过。
- **构建通过**：只证明指定提交能生成产物，不证明安装和业务流程成功。
- **模拟器通过**：必须记录模拟器设备、方向、分辨率、提交哈希、流程、UI 树或日志证据。
- **真机通过**：必须记录真实设备、系统版本、HAP 哈希和完整运行证据。
- **线上通过**：必须记录端点、HTTP 状态、业务字段、提交/部署版本和不含秘密的时间信息。
- **未验证**：缺少对应层级证据时必须明确使用此结论。

执行规则：

1. 证据绑定 Git 提交、HAP SHA-256 和采集时间。其他提交的截图、测试计数或口头结论不得自动沿用。
2. HTTP 200 只证明请求成功到达；还必须验证 Health 的 `status` 和模型字段、Chat SSE 的正文/引用/`done`、Plan 的任务结构、Quiz 的展示题与独立评分结构。
3. 模拟器、真机和视频中的点击坐标必须来自实时 UI 树 bounds；不得写死坐标后把偶然命中写成流程通过。
4. 模型等待、失败或取消必须保留真实状态；不得用模板文本、静态回复、随机数据或测试替身拼出演示成功。
5. 多设备适配只有在至少两个明确设备/窗口环境获得证据后才能陈述；当前安全区实现只能标为**源码确认**，多设备表现为**未验证**。

## 五、产品叙事

### 1. 一句话创新点

> 鸿学伴把真实 Agent 编排、课程依据检索与 HarmonyOS 端 ArkData 画像连接成“计划、学习、测验、错题、再学”的可解释闭环，并通过服务卡片和学习提醒在合适时刻主动把下一步送到学生面前。
