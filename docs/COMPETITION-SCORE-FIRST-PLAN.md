## 三、证据等级与真实性红线

全文只使用以下七种证据等级：

- **源码确认**：只证明源码、配置、文档或数据存在，不证明能够构建或运行。
- **静态诊断通过**：只证明 lint、类型检查或 ArkTS 诊断通过。
- **构建通过**：只证明指定提交能生成产物，不证明安装和业务流程成功。
- **模拟器通过**：必须记录模拟器设备、方向、分辨率、提交哈希、流程、UI 树或日志证据。
- **真机通过**：必须记录真实设备、系统版本、HAP 哈希和完整运行证据。
- **线上通过**：必须记录端点、HTTP 状态、业务字段、提交/部署版本和不含秘密的时间信息。
- **未验证**：缺少对应层级证据时必须明确使用此结论。

执行规则：

1. 证据绑定 Git 提交、HAP SHA-256 和采集时间。其他提交的截图、测试计数或口头结论不得自动沿用。
2. HTTP 200 只证明请求成功到达；还必须验证 Health 的 `status` 和模型字段、Chat SSE 的正文/引用/`done`、Plan 的任务结构、Quiz 的展示题与独立评分结构。
3. 模拟器、真机和视频中的点击坐标必须来自实时 UI 树 bounds；不得写死坐标后把偶然命中写成流程通过。
4. 模型等待、失败或取消必须保留真实状态；不得用模板文本、静态回复、随机数据或测试替身拼出演示成功。
5. 多设备适配只有在至少两个明确设备/窗口环境获得证据后才能陈述；当前安全区实现只能标为**源码确认**，多设备表现为**未验证**。

## 五、产品叙事

### 1. 一句话创新点

> 鸿学伴把真实 Agent 编排、课程依据检索与 HarmonyOS 端 ArkData 画像连接成“计划、学习、测验、错题、再学”的可解释闭环，通过服务卡片持续呈现下一步，并允许学生手动创建对应的系统提醒。

### 2. 800 字以内项目介绍草案

> 高校学生的学习资料、计划、练习和复盘常散落在多个工具中，通用 AI 又难以持续理解课程上下文。鸿学伴是一款 HarmonyOS 原生 AI 学习伙伴，以真实课程内容和端侧学习数据为基础，串联“今日任务、课程学习、依据检索、学伴答疑、测验评分、错题复盘”。云端 Agent 完成画像理解、知识检索、计划、出题、评估与安全审核，模型密钥只保存在服务端。HarmonyOS 端使用 ArkUI 构建“今日、课程、学伴、我的”四个入口，以 ArkData 保存画像、计划、进度、错题和会话，使云端保持无状态；服务卡片持续呈现下一项学习任务，学生也可在首页手动创建对应的系统提醒。课程内容与题库支持离线阅读和确定性评分，AI 不可用时明确报错，不用模板冒充回答。作品目前覆盖数据结构、操作系统、计算机网络三门课程；题库由 Web 单一源生成端侧 JSON，知识关系用于组织循序学习。五分钟演示将从服务卡片进入课程，展示带课程依据的真实问答，再完成测验和本地进度回写。项目面向高校课程助学，内容结构可扩展到更多课程，但学习效果、真机适配和规模化价值只按实际验证结果陈述。
