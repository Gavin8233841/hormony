## Topic 1: OSI与TCP/IP模型

### 知识切片引用
- cs103_k01: OSI参考模型由ISO提出，将网络通信划分为七层：物理层、数据链路层、网络层、传输层、会话层、表示层和应用层...
- cs103_k02: TCP/IP模型是互联网实际使用的协议栈模型，将网络分为四层：网络接口层、网际层、传输层和应用层...
- cs103_k03: 数据在网络中传输时经历封装与解封装过程。发送端从应用层向下逐层添加协议首部...
- cs103_k04: OSI模型中层与层之间的交互通过服务访问点（SAP）实现。每一层通过SAP向其上层提供服务...

### 现实案例
- **标题**：现实案例：邮政系统分层投递
- **正文**：寄一封信时，你只需写好信纸装信封贴邮票投入邮箱，邮政内部按分拣、运输、投递等环节分层处理，每层只完成自己的职责。网络分层也是如此：应用层像写信人，传输层像装信封并标注收发人，网络层像分拣中心选择运输路线，数据链路层像运输车在相邻站点间搬运，物理层像公路本身。每层只与相邻层交互，互不干扰，只要接口不变就能独立演进——这正是分层架构模块化的优势。

### 逐步示例
- **标题**：HTTP GET请求从应用层到物理层的完整封装过程
- **步骤1**：应用层生成消息 → 浏览器构造"GET /index.html HTTP/1.1"请求行和首部字段，形成应用层消息（Message），PDU类型为Message
- **步骤2**：传输层添加TCP首部 → TCP在该消息前添加20字节首部（含源端口、目的端口80、序列号、确认号等），形成报文段（Segment），PDU变为Segment
- **步骤3**：网络层添加IP首部 → IP在报文段前添加20字节首部（含源IP、目的IP、TTL=64、协议号6等），形成数据报（Datagram），PDU变为Datagram
- **步骤4**：数据链路层添加帧首部和帧尾 → 以太网驱动添加14字节帧首部（含源MAC、目的MAC、类型0x0800）和4字节FCS校验尾，形成数据帧（Frame），PDU变为Frame
- **步骤5**：物理层转换为比特流 → 网卡将帧转换为电信号在线缆上传输，PDU变为比特流（Bit），接收端逐层向上解封装还原原始消息

### 主动练习 1（步骤排序）
- **类型**：step_order
- **题目**：以下是在TCP/IP模型中，发送端从应用层数据到物理层比特流的封装过程。请将打乱的步骤排列为正确的封装顺序
- **打乱步骤**：
  - A. 网络层添加IP首部（源IP、目的IP、TTL等）形成数据报
  - B. 物理层将帧转换为比特流在线路上传输
  - C. 应用层生成HTTP请求消息
  - D. 数据链路层添加帧首部（源MAC、目的MAC）和FCS帧尾形成数据帧
  - E. 传输层添加TCP首部（源端口、目的端口、序列号等）形成报文段
- **正确顺序**：C → E → A → D → B
- **反馈**：封装过程严格按从上到下的层次顺序进行：应用层先产生消息，传输层加TCP首部变报文段，网络层加IP首部变数据报，数据链路层加帧头帧尾变数据帧，最后物理层转为比特流。每一层的首部包含该层协议的控制信息（端口号、IP地址、MAC地址等），接收端逐层向上剥离首部完成解封装。这与知识切片 cs103_k03 所述"发送端从应用层向下逐层添加协议首部"一致
- **来源**：计算机网络：自顶向下方法（Kurose & Ross）；知识切片 cs103_k03

### 主动练习 2（状态推演）
- **类型**：state_trace
- **题目**：一个DNS查询消息从应用层发出，依次经过TCP/IP模型的各层。请推演该消息在每一层的协议数据单元（PDU）类型变化
- **初始状态**：应用层已生成DNS查询消息，PDU为Message
- **操作序列**：
  1. 传输层处理：添加UDP首部（8字节，含源端口、目的端口53）
  2. 网络层处理：添加IP首部（20字节，含源IP、目的IP）
  3. 数据链路层处理：添加以太网帧首部和FCS帧尾
  4. 物理层处理：转换为比特流在线路上传输
- **推演过程**：
  - 操作1后：PDU从 Message 变为 Segment（报文段）
  - 操作2后：PDU从 Segment 变为 Datagram（数据报）
  - 操作3后：PDU从 Datagram 变为 Frame（数据帧）
  - 操作4后：PDU从 Frame 变为 Bit（比特流）
- **最终状态**：到达物理层时PDU为Bit（比特流），接收端将逆向从Bit逐层还原为Message
- **答案**：Message → Segment → Datagram → Frame → Bit；最终为 Bit（比特流）
- **反馈**：OSI各层PDU依次为：物理层-Bit、数据链路层-Frame、网络层-Packet(Datagram)、传输层-Segment、应用层-Message。DNS使用UDP而非TCP，因此传输层PDU虽为报文段但承载的是UDP报文。注意TCP/IP模型将OSI上三层合并为应用层，但PDU名称仍沿用OSI定义。这与知识切片 cs103_k03 和 cs103_k04 中PDU通过封装保持独立性的描述一致
- **来源**：计算机网络：自顶向下方法（Kurose & Ross）；知识切片 cs103_k03、cs103_k04

### 现实案例
- **标题**：现实案例：办公楼门禁登记系统
- **正文**：办公楼的门禁卡上有唯一卡号（类比MAC地址48位唯一标识），前台登记卡号与办公室的对应关系（类比交换机MAC地址表）。访客刷卡时前台查表放行（类比交换机查表单播转发）；遇到未登记的卡号则广播通知所有楼层（类比泛洪）。不同部门可划分独立门禁区域互不干扰（类比VLAN隔离广播域），跨部门通行需经过前台转接（类比不同VLAN间需三层路由）。登记表有过期时间，长期未用的记录会自动删除（类比MAC地址老化机制）。

### 逐步示例
- **标题**：交换机MAC地址学习与帧转发过程
- **步骤1**：初始状态 → 交换机MAC地址表为空。端口1连接主机A（MAC=AA:AA），端口2连接主机B（MAC=BB:BB），端口3连接主机C（MAC=CC:CC）
- **步骤2**：主机A发送帧给主机C → 交换机从端口1收到帧，源MAC=AA:AA。将(AA:AA, 端口1)写入MAC地址表，完成地址学习
- **步骤3**：查找目的MAC=CC:CC → MAC地址表中无CC:CC的记录，交换机向除端口1外的所有端口（端口2、端口3）泛洪该帧
- **步骤4**：主机C收到帧并回复 → 主机C从端口3发送回复帧给主机A，源MAC=CC:CC。交换机将(CC:CC, 端口3)写入MAC地址表
- **步骤5**：查找目的MAC=AA:AA → 表中存在(AA:AA, 端口1)且不同于入端口3，交换机从端口1单播转发，不再泛洪。此后A与C之间的通信均通过查表精确转发

### 主动练习 1（状态推演）
- **类型**：state_trace
- **题目**：一台交换机有3个端口，初始MAC地址表为空。端口1连PC1(MAC=11)，端口2连PC2(MAC=22)，端口3连PC3(MAC=33)。请推演以下操作序列后交换机MAC地址表的内容
- **初始状态**：MAC地址表为空
- **操作序列**：
  1. PC1发送帧给PC3 → 交换机从端口1收帧，学习(11, 端口1)；表中无33，泛洪到端口2和端口3
  2. PC3回复帧给PC1 → 交换机从端口3收帧，学习(33, 端口3)；表中有11(端口1)，从端口1单播转发
  3. PC2发送帧给PC1 → 交换机从端口2收帧，学习(22, 端口2)；表中有11(端口1)，从端口1单播转发
- **最终状态**：MAC地址表包含3条记录：(11, 端口1)、(33, 端口3)、(22, 端口2)。此时三台主机互相通信均可查表单播转发，无需泛洪
- **答案**：(11, 端口1)、(33, 端口3)、(22, 端口2)
- **反馈**：交换机每次收到帧都执行两个动作：先学习源MAC与入端口的映射，再查表转发目的MAC。第一次通信时目的MAC不在表中，触发泛洪使帧到达所有端口；目标主机回复后其MAC也被学习，后续通信即可精确转发。交换机每个端口是独立冲突域，全双工模式下无冲突。这与知识切片 cs103_k07 所述"地址学习"和"查表转发"机制一致
- **来源**：计算机网络：自顶向下方法（Kurose & Ross）；知识切片 cs103_k07

### 主动练习 2（步骤排序）
- **类型**：step_order
- **题目**：以下是以太网CSMA/CD协议在节点发送数据时的工作流程。请将打乱的步骤排列为正确的执行顺序
- **打乱步骤**：
  - A. 边发边听——发送过程中持续检测信道上是否有冲突信号
  - B. 随机重发——采用二进制指数退避算法，等待随机时间槽后重新尝试发送
  - C. 先听后发——发送前先监听信道，信道空闲才开始发送
  - D. 冲突停发——检测到冲突立即停止发送，并发送Jam拥塞信号强化冲突
- **正确顺序**：C → A → D → B
- **反馈**：CSMA/CD的四个阶段按时间顺序为：先听后发（载波监听）→ 边发边听（冲突检测）→ 冲突停发（发送Jam信号）→ 随机重发（二进制指数退避）。第n次冲突后从0到2^k-1中随机选择等待时间（k=min(n,10)）。冲突检测要求帧发送时间大于信号往返传播时间，因此以太网规定最小帧长64字节。现代交换式以太网全双工模式下不存在冲突，CSMA/CD已不再需要。这与知识切片 cs103_k06 所述工作流程一致
- **来源**：计算机网络：自顶向下方法（Kurose & Ross）；IEEE 802.3标准；知识切片 cs103_k06

### 现实案例
- **标题**：现实案例：公司分机号系统
- **正文**：公司总机号码类比网络号，分机号类比主机号。行政部将8000-8099分给技术组、8100-8199分给市场组，相当于用子网掩码把一个大网分成多个子网。拨打分机时总机根据号段判断转接到哪个部门，就像路由器用子网掩码判断数据报属于哪个子网。若号码不够用还可以灵活调整号段边界，不再固守"技术组必须4位、市场组必须4位"的规则——这正是CIDR无类别划分的思路，打破了A/B/C类的固定边界。

### 逐步示例
- **标题**：将C类网络192.168.1.0/24划分为/26子网
- **步骤1**：确定原始网络 → C类网络192.168.1.0/24，子网掩码255.255.255.0，主机号8位，可容纳254台主机（主机号全0为网络地址、全1为广播地址不可分配）
- **步骤2**：选择子网掩码 → 使用/26即255.255.255.192，从主机号8位中借用2位作为子网号，剩余6位为主机号
- **步骤3**：计算子网数量 → 借用2位，可划分2^2=4个子网
- **步骤4**：计算每个子网的主机容量 → 剩余主机号6位，每个子网可分配2^6-2=62台主机（减去网络地址和广播地址）
- **步骤5**：确定各子网地址范围 → 子网0：192.168.1.0~63（网络地址.0，广播地址.63）；子网1：192.168.1.64~127（网络地址.64，广播地址.127）；子网2：192.168.1.128~191（网络地址.128，广播地址.191）；子网3：192.168.1.192~255（网络地址.192，广播地址.255）

### 主动练习 1（代码填空）
- **类型**：code_fill
- **题目**：以下Python代码通过IP地址和子网掩码计算网络地址。请填空使计算正确
- **代码**：
```python
ip = [192, 168, 1, 130]
mask = [255, 255, 255, 192]
network = []
for i in range(4):
    network.append(__________)  # 填入计算网络地址的表达式
print("网络地址:", ".".join(map(str, network)))
```
- **答案**：`ip[i] & mask[i]`
- **反馈**：网络地址通过IP地址与子网掩码按位与运算得到。Python中`&`是按位与运算符。逐字节计算：192&255=192, 168&255=168, 1&255=1, 130&192=128（130的二进制10000010与192的二进制11000000按位与得10000000即128）。因此网络地址为192.168.1.128，对应/26子网划分中的子网2。这与知识切片 cs103_k10 所述"子网掩码与IP地址按位与运算后得到网络地址"一致
- **来源**：计算机网络：自顶向下方法（Kurose & Ross）；知识切片 cs103_k10

### 主动练习 2（输出预测）
- **类型**：output_predict
- **题目**：路由器的路由表中有以下4条路由条目，目的地址为10.1.2.5的IP数据报到达后，路由器将选择哪个下一跳转发？请预测结果
- **路由表内容**：
```
目的网络          前缀长度  下一跳
10.0.0.0/8       /8       R1
10.1.0.0/16      /16      R2
10.1.2.0/24      /24      R3
0.0.0.0/0        /0       R4（默认路由）
```
- **预测内容**：目的地址10.1.2.5同时匹配4条路由（/8、/16、/24、/0），路由器按最长前缀匹配原则选择前缀最长的条目
- **答案**：选择R3（10.1.2.0/24），因为/24前缀长度最长（最具体），匹配最精确
- **反馈**：最长前缀匹配原则要求当多条路由都匹配目标地址时，选择前缀最长（最具体）的路由条目。10.1.2.5匹配/8（10.x.x.x）、/16（10.1.x.x）、/24（10.1.2.x）和/0（任意），其中/24前缀长度24最长，因此选R3。默认路由0.0.0.0/0前缀长度为0，是最后兜底选择。CIDR通过最长前缀匹配实现了路由聚合与精确路由的共存。这与知识切片 cs103_k11 所述"路由器选择前缀最长（最具体）的路由"一致
- **来源**：计算机网络：自顶向下方法（Kurose & Ross）；RFC 4632（CIDR）；知识切片 cs103_k11

## Topic 4: TCP流量控制与拥塞控制

### 知识切片引用
- cs103_k19: TCP滑动窗口是实现流量控制的核心机制。发送方维护发送窗口，窗口大小由接收方通过ACK报文段中的窗口字段（rwnd）通告...
- cs103_k20: TCP拥塞控制通过拥塞窗口（cwnd）限制发送速率。慢启动阶段cwnd初始为1，每收到一个ACK加1，每经过一个RTT翻倍呈指数增长...
- cs103_k21: 拥塞避免算法在cwnd达到ssthresh后启动，将cwnd增长方式从指数改为线性——每个RTT增加1个MSS...
- cs103_k22: 快重传算法要求接收方每收到一个失序报文段就立即发送重复ACK，发送方连续收到3个重复ACK时立即重传丢失的报文段...
- cs103_k23: 快恢复是快重传的配套算法。收到3个重复ACK时，将ssthresh和cwnd都设为当前cwnd的一半，然后进入拥塞避免阶段的线性增长...

### 现实案例
- **标题**：现实案例：水库调度系统
- **正文**：水库向下游供水时，闸门开度类比拥塞窗口（cwnd）。刚开始小开度试探（慢启动），确认河道能承受后逐步加大开度（指数增长）；到达警戒水位线（ssthresh）后改为缓慢增加（拥塞避免线性增长）。若发现下游严重溢洪（超时），立即关小闸门到最小重来；若只是局部波动（3个重复ACK），则只减半开度而非全关（快恢复）。下游水厂蓄水池容量类比接收窗口（rwnd），实际放水量取闸门开度和水厂容量的较小值——同时不淹没下游网络和不让水厂溢出。

### 逐步示例
- **标题**：TCP拥塞窗口从慢启动到快恢复的变化过程
- **步骤1**：慢启动阶段 → cwnd=1，ssthresh=16。每收到一个ACK，cwnd加1，每经过一个RTT翻倍：1→2→4→8→16（4个RTT完成指数增长）
- **步骤2**：进入拥塞避免 → cwnd=16达到ssthresh，切换为线性增长。每经过一个RTT，cwnd增加1个MSS：16→17→18→...→24（8个RTT）
- **步骤3**：触发快重传 → cwnd=24时收到3个重复ACK，判定报文段丢失。ssthresh=24/2=12，cwnd=ssthresh=12（快恢复，cwnd不重置为1）
- **步骤4**：快恢复后继续拥塞避免 → cwnd=12，以线性方式增长：12→13→14→...，温和探测网络带宽
- **步骤5**：对比超时场景 → 若cwnd=24时不是收到3个重复ACK而是RTO超时，则ssthresh=24/2=12，cwnd重置为1，重新进入慢启动阶段（与快恢复的区别在于cwnd是否归1）

### 主动练习 1（状态推演）
- **类型**：state_trace
- **题目**：一个TCP连接初始cwnd=1，ssthresh=16。请推演以下操作序列后cwnd和ssthresh的最终值
- **初始状态**：cwnd=1, ssthresh=16
- **操作序列**：
  1. 经过4个RTT的慢启动（cwnd每RTT翻倍）→ cwnd从1经2、4、8变为16，达到ssthresh
  2. 进入拥塞避免，经过2个RTT线性增长 → cwnd从16变为17，再变为18
  3. 收到3个重复ACK，触发快重传和快恢复 → ssthresh=floor(18/2)=9，cwnd=ssthresh=9
  4. 继续拥塞避免1个RTT → cwnd从9变为10
- **推演过程**：
  - 操作1后：cwnd=16, ssthresh=16（慢启动阶段指数增长，4个RTT：1→2→4→8→16）
  - 操作2后：cwnd=18, ssthresh=16（拥塞避免线性增长，每RTT加1）
  - 操作3后：cwnd=9, ssthresh=9（快恢复：ssthresh=cwnd/2=9，cwnd=ssthresh=9，不归1）
  - 操作4后：cwnd=10, ssthresh=9（拥塞避免线性增长1个RTT）
- **最终状态**：cwnd=10, ssthresh=9
- **答案**：cwnd=10，ssthresh=9
- **反馈**：慢启动阶段cwnd每RTT翻倍（指数增长），4个RTT后从1增长到16。达到ssthresh后切换为拥塞避免，每RTT仅加1（线性增长）。收到3个重复ACK触发快重传：ssthresh降为当前cwnd的一半（9），cwnd也设为ssthresh值（9），不重置为1——这是因为3个重复ACK说明网络仍能传输报文段，丢包可能只是偶然。这与知识切片 cs103_k20、cs103_k23 所述慢启动、快恢复机制一致
- **来源**：计算机网络：自顶向下方法（Kurose & Ross）；RFC 5681（TCP Congestion Control）；知识切片 cs103_k20、cs103_k23

### 主动练习 2（步骤排序）
- **类型**：step_order
- **题目**：以下是TCP Reno拥塞控制从连接建立到遇到3个重复ACK的各阶段。请将打乱的步骤排列为正确的时间顺序
- **打乱步骤**：
  - A. 收到3个重复ACK，ssthresh设为当前cwnd的一半，cwnd设为ssthresh值（快恢复）
  - B. cwnd从1开始，每经过一个RTT翻倍（慢启动指数增长）
  - C. cwnd达到ssthresh后，每经过一个RTT增加1个MSS（拥塞避免线性增长）
  - D. 快恢复后，cwnd以线性方式继续增长探测网络带宽
- **正确顺序**：B → C → A → D
- **反馈**：TCP Reno拥塞控制的时间线为：连接建立时cwnd=1进入慢启动（B），指数增长快速探测带宽；cwnd达到ssthresh后切换到拥塞避免（C），线性增长温和试探；收到3个重复ACK触发快重传和快恢复（A），ssthresh减半但cwnd不归1；快恢复后继续拥塞避免的线性增长（D）。若发生超时而非3个重复ACK，则cwnd重置为1重新慢启动，这是TCP Tahoe与Reno的关键区别。这与知识切片 cs103_k20、cs103_k21、cs103_k23 所述四阶段算法一致
- **来源**：计算机网络：自顶向下方法（Kurose & Ross）；RFC 5681（TCP Congestion Control）；知识切片 cs103_k20、cs103_k21、cs103_k23

### 现实案例
- **标题**：现实案例：明信片投递
- **正文**：寄明信片不需要提前和邮局建立联系（无连接），写好地址直接投递，丢了邮局不负责你自己重寄（不可靠）。明信片轻便快捷（首部开销小仅8字节），适合寄简短通知如"图书馆几点开门"（DNS查询）。相比之下寄挂号信（TCP）要登记签收、保证送达，安全但繁琐耗时。如果只是问一句话，明信片足够了；但寄重要文件还得用挂号信。实时视频通话更像明信片——偶尔丢几帧无所谓，但延迟太大对方就听不清了，所以选UDP而非TCP。

### 逐步示例
- **标题**：UDP校验和伪首部的构造与计算过程
- **步骤1**：构造伪首部 → 伪首部共12字节，包含源IP地址（4字节）、目的IP地址（4字节）、协议号（1字节，值为17，补零到2字节）、UDP长度（2字节，含首部和数据）。伪首部不实际传输，仅用于校验和计算

- **步骤3**：按16位字分组 → 将拼接后的数据按每16位（2字节）为一组进行划分。若数据长度为奇数字节，末尾补零凑齐16位
- **步骤4**：反码求和 → 对所有16位字进行二进制反码求和。计算中将所有16位字相加，若有进位则回卷（将进位加回低位）
- **步骤5**：取反填入校验和字段 → 将求和结果取反码，填入UDP首部的校验和字段。接收方用相同方法计算后验证，若全1则正确，否则丢弃数据报

### 主动练习 2（状态推演）
- **类型**：state_trace
- **题目**：发送方依次通过UDP发送3个数据报D1、D2、D3，接收方无序号确认和重传机制。请推演以下网络传输操作后接收方的最终状态
- **初始状态**：发送方队列中有D1、D2、D3三个UDP数据报待发送，接收方缓存为空
- **操作序列**：
  1. D1正常到达接收方 → 接收方收到D1，缓存中有[D1]
  2. D2在网络中因拥塞被丢弃 → 接收方未收到D2，发送方不知道丢包（UDP无确认和重传机制）
  3. D3经过不同路径先到达 → 接收方收到D3，缓存中有[D1, D3]（乱序到达，UDP不保证有序）
  4. 等待超时，D2始终未到达 → 接收方最终持有D1和D3，D2永久丢失
- **推演过程**：
  - 操作1后：接收方缓存 = [D1]（正常到达）
  - 操作2后：接收方缓存 = [D1]（D2丢失，无反馈机制）
  - 操作3后：接收方缓存 = [D1, D3]（D3乱序到达，无排序机制）
  - 操作4后：接收方缓存 = [D1, D3]（D2永久丢失，应用层需自行处理）
- **最终状态**：接收方持有D1和D3，缺失D2，且到达顺序为D1→D3（乱序）。与TCP不同，UDP不保证可靠交付、不保证顺序、不重传丢失数据
- **答案**：接收方缓存为 [D1, D3]，D2 丢失且不会由 UDP 重传
- **反馈**：UDP不提供流量控制、拥塞控制、重传和序号机制，数据报可能丢失、重复或乱序到达。D2丢失后发送方无感知，D3乱序到达后接收方不重排——可靠性需由应用层自行保障。例如QUIC协议在UDP之上实现了可靠传输和前向纠错。这与知识切片 cs103_k24 所述"数据报可能丢失、重复或乱序到达，可靠性需要由应用层自行保障"一致

## Topic 6: HTTPS与TLS

### 知识切片引用
- cs103_k32: TLS握手过程在TCP连接建立后进行。客户端发送ClientHello，包含支持的TLS版本、密码套件列表和客户端随机数...
- cs103_k33: TLS证书验证基于公钥基础设施（PKI）的信任链。终端实体证书由中间CA签发，中间CA由根CA签发，根CA证书预装在信任库中...
- cs103_k34: TLS密钥交换用于安全地协商共享的预主密钥。RSA密钥交换不具备前向安全性，DHE/ECDHE具备前向安全性...
- cs103_k35: 前向安全性是指即使长期私钥泄露，过去已完成的通信会话也无法被解密。TLS 1.3强制使用ECDHE和DHE，弃用RSA密钥交换...

### 现实案例
- **标题**：现实案例：身份证签发与银行验证
- **正文**：你去银行办业务，出示身份证。身份证由公安局（根CA）授权的派出所（中间CA）签发。银行柜员验证身份证真伪（验证证书签名）、检查是否过期（有效期）、核对照片是否是你本人（域名匹配SAN/CN）、查询是否被挂失（OCSP/CRL吊销检查）。验证通过后双方约定一个临时暗号（会话密钥）交流业务，用完即弃。即使日后公安局的签发章被盗（长期私钥泄露），以前用临时暗号办过的业务仍无法被还原——因为临时暗号用后即销，这正是前向安全性的含义。

### 逐步示例
- **标题**：TLS 1.2握手完整过程（使用ECDHE密钥交换）
- **步骤1**：ClientHello → 客户端发送支持的TLS版本（如1.2）、密码套件列表（如TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256）和客户端随机数（Client Random，32字节）
- **步骤2**：ServerHello + 证书 + 密钥交换 → 服务器回复选定的TLS版本和密码套件，发送服务器随机数（Server Random，32字节）、数字证书（含服务器公钥）和ServerKeyExchange（携带ECDHE临时公钥参数）
- **步骤3**：客户端验证证书 → 客户端逐级验证证书签名链（终端→中间CA→根CA）、检查有效期、验证域名匹配SAN字段、查询OCSP/CRL确认未吊销
- **步骤4**：ClientKeyExchange + CCS + Finished → 客户端发送自己的ECDHE临时公钥，发送ChangeCipherSpec（通知后续使用加密）和Finished（加密验证握手完整性）
- **步骤5**：Server CCS + Finished → 服务器发送ChangeCipherSpec和Finished，握手完成
- **步骤6**：对称加密通信 → 双方利用Client Random、Server Random和ECDHE协商出的预主密钥，通过PRF函数计算主密钥和会话密钥，后续应用数据用对称加密（如AES-GCM）保护

## Topic 8: 路由算法与协议

### 知识切片引用
- cs103_k40: 路由算法分为距离向量算法和链路状态算法两大类。距离向量算法中每个节点仅知道邻居和到邻居的距离，周期性交换路由表（Bellman-Ford方程）...
- cs103_k41: RIP是基于距离向量算法的IGP，以跳数为度量值，最大15跳，16跳视为不可达。通过水平分割、毒性逆转和触发更新缓解计数到无穷问题...
- cs103_k42: OSPF是基于链路状态算法的IGP，使用Dijkstra算法计算最短路径树。支持多区域分层设计，区域0为骨干区域...
- cs103_k43: BGP是自治系统间的路径向量路由协议，基于AS_PATH等策略属性选择最优路径，使用TCP端口179建立连接...

### 现实案例
- **标题**：现实案例：城际公路导航
- **正文**：开车导航有两种思路。一种是只问路边当地人"下一个镇多远"（距离向量算法），每个路口的司机互相交换距离信息，逐渐拼出最短路线，但信息传播慢且可能以讹传讹（计数到无穷问题）。另一种是先获取全省完整公路地图（链路状态算法），自己用导航算法算出最短路径，准确快速但需要存储整张地图。城市间跨省行驶时，各省交通厅各自管理省内道路（OSPF内部网关协议），省际路口由国道编号指引（BGP外部网关协议），按行政策略而非纯距离选择跨省路径。

### 逐步示例
- **标题**：使用Dijkstra算法计算R1到R4的最短路径
- **步骤1**：初始化 → 源节点R1。已知直连链路距离：R1→R2=2，R1→R3=5。R4距离为无穷大。已确定集合S={R1}
- **步骤2**：选择最近节点 → R2距离最短（2），将R2加入S。S={R1,R2}。检查R2的邻居：R2→R3=1，因此R1→R2→R3=2+1=3 < 5，更新R3距离为3
- **步骤3**：选择下一个最近节点 → R3距离最短（3），将R3加入S。S={R1,R2,R3}。检查R3的邻居：R3→R4=4，因此R1→R2→R3→R4=3+4=7 < 无穷大，更新R4距离为7
- **步骤4**：选择下一个最近节点 → R4距离最短（7），将R4加入S。S={R1,R2,R3,R4}。所有节点已确定
- **步骤5**：确定最短路径 → R1到R4的最短路径为R1→R2→R3→R4，总距离=7。注意直连路径R1→R3=5虽短于R1→R2→R3=3的单独段，但经R2中转到R3（距离3）比直连（距离5）更优，链路状态算法通过全局拓扑发现了这一更优路径

### 主动练习 1（状态推演）
- **类型**：state_trace
- **题目**：路由器R1运行RIP协议（度量值为跳数），初始路由表如下。R2向R1发送了距离向量更新。请推演R1更新后的路由表
- **初始状态**：R1路由表：N1(距离0, 直连)、N2(距离2, 经R2)、N3(距离4, 经R3)。R2到各网段的距离：N1=1, N2=0, N3=1
- **操作序列**：
  1. R1收到R2的距离向量更新（R2到N1=1, N2=0, N3=1）
  2. 对N1：原距离0（直连）vs R2通告1+1=2，0 < 2，保持不变
  3. 对N2：原距离2（经R2）vs R2通告0+1=1，1 < 2，更新为距离1（经R2）
  4. 对N3：原距离4（经R3）vs R2通告1+1=2，2 < 4，更新为距离2（经R2）
- **推演过程**：
  - 操作2后：N1=0(直连)，保持不变（直连距离0最优）
  - 操作3后：N2=1(经R2)，从2更新为1（R2是N2的直连网段，经R2只需1跳）
  - 操作4后：N3=2(经R2)，从4更新为2（经R2到N3只需2跳，比经R3的4跳更短）
- **最终状态**：R1路由表为：N1=0(直连)、N2=1(经R2)、N3=2(经R2)。Bellman-Ford方程：新距离=min(原距离, 邻居到目标距离+到邻居距离)
- **答案**：N1=0（直连）、N2=1（经R2）、N3=2（经R2）
- **反馈**：距离向量算法使用Bellman-Ford方程更新路由：D(x,y)=min(D(x,y), D(x,v)+D(v,y))。R1收到R2的距离向量后，对每个目的网络比较原路径和新路径（经R2）的距离，取较小值。N1直连最优不更新，N2和N3经R2更短故更新。RIP每30秒交换距离向量，最大15跳限制防止计数到无穷。这与知识切片 cs103_k40、cs103_k41 所述Bellman-Ford方程和RIP机制一致
- **来源**：计算机网络：自顶向下方法（Kurose & Ross）；知识切片 cs103_k40、cs103_k41

## Topic 9: 网络安全基础

### 知识切片引用

### 现实案例
- **标题**：现实案例：密封信件与签章
- **正文**：对称加密像用同一把钥匙锁箱子和开箱子——快但钥匙怎么安全给对方是难题（密钥分发问题）。非对称加密像你有一把公开的锁（公钥），任何人都能锁上但只有你有钥匙（私钥）能打开。数字签名则反过来：你用私钥盖章（签名），别人用你的公开印章模板（公钥）验证真伪，既证明是你盖的又无法伪造。实际通信中先用非对称方式安全交换一把对称钥匙，再用这把快钥匙加密大量数据——这就是混合加密体制，兼顾安全和效率。

### 逐步示例
- **标题**：混合加密通信的完整过程（RSA + AES）
- **步骤1**：生成对称密钥 → 发送方Alice生成一次性AES会话密钥K（如256位），用于加密大量数据，因AES加解密速度快适合大数据量
- **步骤2**：用公钥加密对称密钥 → Alice用接收方Bob的RSA公钥加密AES密钥K，得到密文C_key。RSA解决了对称密钥的安全分发问题
- **步骤3**：用对称密钥加密数据 → Alice用AES密钥K加密原始数据（如文件），得到密文C_data。AES加密速度远快于RSA，适合加密大量数据
- **步骤4**：发送密文 → Alice将C_key（加密的对称密钥）和C_data（加密的数据）一起发送给Bob
- **步骤5**：用私钥解密对称密钥 → Bob收到后，先用自己的RSA私钥解密C_key，恢复出AES密钥K。只有Bob的私钥能解密，保证了密钥分发的安全性
- **步骤6**：用对称密钥解密数据 → Bob用恢复的AES密钥K解密C_data，获得原始数据。整个过程中RSA仅用于加密少量数据（对称密钥），AES负责加密大量数据，兼顾了安全性和效率
