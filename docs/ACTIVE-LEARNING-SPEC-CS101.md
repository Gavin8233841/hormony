## Topic 1: 二叉树与BST

### 知识切片引用
- cs101_k14: 二叉树是每个节点最多有两个子树（左子树和右子树）的树形结构，子树有左右之分，次序不能颠倒...
- cs101_k15: 二叉树遍历按访问根节点的时机分为前序（根-左-右）、中序（左-根-右）、后序（左-右-根）...
- cs101_k16: 二叉搜索树（BST，Binary Search Tree）满足：左子树所有节点值小于根，右子树所有节点值大于根...
- cs101_k17: 对二叉搜索树进行中序遍历，得到的是严格递增的有序序列，这是 BST 最本质的性质...
- cs101_k18: 二叉树可采用顺序存储和链式存储。顺序存储用数组按下标映射，节点 i 的左孩子在 2i+1...

### 现实案例
- **标题**：现实案例：组织架构树与人员查找
- **正文**：公司组织架构像一棵二叉树：CEO 是根节点，直接下属是左右子节点，层层向下展开。在 BST 式的组织架构中，每个管理者左边的下属工号都比自己小，右边的都比自己大。找某位员工时从 CEO 开始，比当前管理者工号小就往左走，大就往右走。如果管理层级平衡（接近 log n 层），查找很快；如果公司变成线性链条（每人只管一人），查找退化为逐级遍历。这正是 BST 平衡性决定查找效率 O(h) 的直观体现。

### 逐步示例
- **标题**：在 BST 中依次插入 50, 30, 70, 40, 60 并查找 60
- **步骤1**：插入 50 → 50 作为根节点，此时树中仅有 {50}
- **步骤2**：插入 30 → 30 < 50，进入左子树，左子树为空，30 成为 50 的左孩子。树结构：50(左:30)
- **步骤3**：插入 70 → 70 > 50，进入右子树，右子树为空，70 成为 50 的右孩子。树结构：50(左:30, 右:70)
- **步骤4**：插入 40 → 40 < 50 进入左子树到达 30；40 > 30 进入右子树为空，40 成为 30 的右孩子。树结构：50(左:30(右:40), 右:70)
- **步骤5**：插入 60 → 60 > 50 进入右子树到达 70；60 < 70 进入左子树为空，60 成为 70 的左孩子。树结构：50(左:30(右:40), 右:70(左:60))
- **步骤6**：查找 60 → 60 > 50 进右子树到 70；60 < 70 进左子树到 60，匹配成功。共比较 3 次，体现了 BST 查找路径长度等于目标节点深度加 1

### 主动练习 1（代码填空）
- **类型**：code_fill
- **题目**：以下是在 BST 中递归插入节点的 C++ 代码，请填写空缺部分使插入逻辑正确
- **代码**：
```cpp
struct TreeNode {
    int val;
    TreeNode* left;
    TreeNode* right;
};

TreeNode* insert(TreeNode* root, int val) {
    if (root == nullptr) {
        return new TreeNode{val, nullptr, nullptr};
    }
    if (val < root->val) {
        root->left = ________;  // 填空1
    } else if (val > root->val) {
        root->right = ________;  // 填空2
    }
    return root;
}
```
- **答案**：填空1 为 `insert(root->left, val)`；填空2 为 `insert(root->right, val)`
- **反馈**：BST 插入的核心是沿搜索路径递归向下定位空位。当 val 小于当前节点值时递归插入左子树并重新链接左指针，大于时递归插入右子树并重新链接右指针。若先修改 root->left 再递归会导致原子树丢失。注意相等时不插入（保持 BST 无重复节点），这是与知识切片 cs101_k16 中"插入类似查找定位后新建叶节点"一致的行为
- **来源**：数据结构与算法分析（Mark Allen Weiss）；知识切片 cs101_k16

### 主动练习 2（步骤排序）
- **类型**：step_order
- **题目**：给定如下 BST，请将对它进行中序遍历的步骤排列为正确执行顺序
```
        50
       /  \
      30   70
       \   /
       40 60
```
- **打乱步骤**：
  - A. 访问根节点 50
  - B. 递归遍历 50 的右子树（以 70 为根）
  - C. 递归遍历 70 的左子树（以 60 为根）
  - D. 递归遍历 50 的左子树（以 30 为根）
  - E. 访问节点 40
  - F. 访问节点 30
  - G. 递归遍历 30 的右子树（以 40 为根）
  - H. 访问节点 60
  - I. 访问节点 70
- **正确顺序**：D → F → G → E → A → B → C → H → I
- **反馈**：中序遍历的顺序是"左子树 → 根 → 右子树"。先递归遍历 50 的左子树（D），在左子树中以 30 为根：先访问 30（F），再遍历 30 的右子树（G）访问 40（E）。回到根访问 50（A）。然后递归遍历 50 的右子树（B），在右子树中以 70 为根：先遍历 70 的左子树（C）访问 60（H），再访问 70（I）。最终输出序列为 30, 40, 50, 60, 70，是严格递增的，验证了知识切片 cs101_k17 所述 BST 中序遍历得到有序序列的性质
- **来源**：数据结构与算法分析（Mark Allen Weiss）；知识切片 cs101_k15、cs101_k17

## Topic 2: AVL树与红黑树

### 知识切片引用
- cs101_k19: AVL 树是一种自平衡二叉搜索树，要求任意节点的左右子树高度差（平衡因子 BF）绝对值不超过 1...
- cs101_k20: 红黑树是一种弱平衡二叉搜索树，通过节点着色和约束维持近似平衡。其五条性质...
- cs101_k21: AVL 树是严格平衡的（|BF|<=1），查找效率高（树高低），但插入删除时旋转频繁，维护成本高...
- cs101_k22: 平衡二叉树的旋转是局部调整操作，不破坏中序有序性。右旋（以 y 为支点）...

### 现实案例
- **标题**：现实案例：图书馆书架的两种整理策略
- **正文**：图书馆频繁从入口侧添加新书，如果不整理，书架会逐渐向一侧倾斜，找书越来越慢。AVL 树就像一个严格的管理员，每放一本书就检查两侧高度差是否超过 1 层，超过立即旋转重排，书架始终保持近乎完美平衡，找书最快但整理动作多。红黑树像一个宽松的管理员，只保证最长一侧不超过最短一侧的两倍，虽然不如 AVL 整齐，但每次添书后的调整次数少（最多 3 次旋转）。频繁添书的图书馆选红黑树策略更省力，查书为主的图书馆选 AVL 策略更快。

### 逐步示例
- **标题**：AVL 树插入 25 导致 LR 型失衡的双旋调整过程
- **初始状态**（AVL 树，所有节点平衡）：
```
       40
      /  \
    20    50
   /  \
  10   30
```
- **步骤1**：插入 25 → 25 < 40 进左子树到 20；25 > 20 进右子树到 30；25 < 30 进左子树为空，25 成为 30 的左孩子
```
       40
      /  \
    20    50
   /  \
  10   30
      /
     25
```
- **步骤2**：计算平衡因子 → BF(30) = 左高1 - 右高0 = 1（正常）；BF(20) = 左高1 - 右高2 = -1（正常）；BF(40) = 左高3 - 右高1 = 2，失衡！
- **步骤3**：确定失衡类型 → 失衡节点是 40，新节点 25 插入在 40 的左孩子 20 的右子树中，属于 LR 型
- **步骤4**：第一次旋转（左旋 20）→ 以 20 为支点左旋：20 的右孩子 30 上提，20 成为 30 的左孩子，30 的原左子树（25）成为 20 的右孩子
```
       40
      /  \
    30    50
   /
  20
 /  \
10   25
```
- **步骤5**：第二次旋转（右旋 40）→ 以 40 为支点右旋：40 的左孩子 30 上提为新子树根，30 的原右子树（空）成为 40 的左子树，40 成为 30 的右孩子
```
       30
      /  \
    20    40
   /  \     \
  10   25   50
```
- **步骤6**：验证平衡 → BF(20)=0, BF(40)=-1, BF(30)=0, 所有节点 |BF| <= 1，恢复平衡。中序遍历 10,20,25,30,40,50 仍为升序，旋转未破坏 BST 有序性

### 主动练习 1（状态推演）
- **类型**：state_trace
- **题目**：给定如下 AVL 树（所有节点当前平衡），依次执行操作：插入 55。请推演插入后的平衡因子变化并给出最终树结构
```
       40
      /  \
    20    50
   /  \     \
  10   30    60
```
- **操作内容**：
  - 初始树中节点 40 为根，左子树 {20,10,30} 高 2，右子树 {50,60} 高 2，BF(40)=0
  - 操作：插入 55
- **答案**：
  1. 55 > 40 进右子树到 50；55 > 50 进右子树到 60；55 < 60 进左子树为空，55 成为 60 的左孩子
  2. 插入后：BF(60) = 左高1 - 右高0 = 1；BF(50) = 左高0 - 右高2 = -2，失衡！
  3. 失衡节点 50，新节点插入在 50 的右孩子 60 的左子树，属于 RL 型
  4. 对 60 右旋：55 上提，60 成为 55 的右孩子
  5. 对 50 左旋：55 上提，50 成为 55 的左孩子
  6. 最终树结构：
```
       40
      /  \
    20    55
   /  \  /  \
  10  30 50  60
```
- **反馈**：RL 型失衡需要先右旋再左旋。注意判断失衡类型的关键是看新节点插入在失衡节点的哪个方向：50 的右子树（R）中 60 的左子树（L），所以是 RL 型。最终 BF(40)=0，整棵树恢复平衡。这与知识切片 cs101_k19 中"RL 型先右旋再左旋"的描述一致
- **来源**：数据结构与算法分析（Mark Allen Weiss）；知识切片 cs101_k19、cs101_k22

### 主动练习 2（步骤排序）
- **类型**：step_order
- **题目**：在红黑树中插入一个新红色节点后，若其父节点也为红色（违反"红节点的子节点必为黑"性质），请将修复操作的步骤排列为正确顺序（假设叔节点为红色的情况）
- **打乱步骤**：
  - A. 将新节点的祖父节点设为红色
  - B. 检查新节点的父节点和叔节点是否均为红色
  - C. 将新节点插入并初始着色为红色
  - D. 将"当前节点"上移到祖父节点，继续向上检查是否仍有连续红节点
  - E. 将父节点和叔节点均重新着色为黑色
  - F. 循环结束后将根节点重新着色为黑色，完成修复
- **正确顺序**：C → B → E → A → D → F
- **反馈**：红黑树插入修复的典型流程：先将新节点着红色（C），检查是否违反红色节点不能连续的性质（B）。当父节点和叔节点均为红色时，将父和叔变黑（E）、祖父变红（A），再把"当前节点"移到祖父位置继续向上检查（D），因为祖父变红可能与其父节点形成新的连续红节点冲突。循环结束后必须将整棵树的根重新着色为黑色（F）；若本轮祖父就是根，省略该步会留下红根，违反知识切片 cs101_k20 的"根为黑"性质。叔父为红时以变色向上传播，不需要在本轮旋转
- **来源**：算法导论（CLRS）；知识切片 cs101_k20

## Topic 3: 图的表示与遍历

### 知识切片引用
- cs101_k23: 邻接矩阵用 n*n 的二维数组表示 n 个顶点的图，A[i][j] 表示顶点 i 到 j 是否有边...
- cs101_k24: 邻接表为每个顶点维护一个链表，存储其所有邻接顶点。空间复杂度为 O(n+e)...
- cs101_k25: 深度优先搜索（DFS）从某顶点出发，沿一条路径尽可能深地探索，遇到死胡同则回溯...
- cs101_k26: 广度优先搜索（BFS）从某顶点出发，先访问所有邻接顶点，再逐层向外扩展，借助队列实现...

### 现实案例
- **标题**：现实案例：地铁线路与社交网络
- **正文**：地铁线路图就是一个图：站点是顶点，相邻站之间的轨道是边。如果你想知道从 A 站到 B 站最少经过几站，BFS 从 A 站出发逐站扩展，第一层是直达站，第二层是换乘一次能到的站，最先到达 B 站时的层数就是最少站数。如果用 DFS，你会沿一条线一路坐到终点再回头，找到的路径不一定最短。选择邻接表存储地铁图（稀疏图）比邻接矩阵节省空间，因为大部分站之间没有直达线路。

### 逐步示例
- **标题**：对以下无向图从顶点 0 执行 BFS 遍历的过程
```
图结构（无向图）：
顶点: 0, 1, 2, 3, 4
边:   0-1, 0-2, 1-3, 2-4
邻接表:
0: [1, 2]
1: [0, 3]
2: [0, 4]
3: [1]
4: [2]
```
- **步骤1**：初始化 → 访问起点 0，标记 visited[0]=true，将 0 入队。队列: [0]，访问序列: [0]
- **步骤2**：弹出队首 0 → 遍历 0 的邻接表 [1, 2]。1 未访问，访问 1 并入队；2 未访问，访问 2 并入队。队列: [1, 2]，访问序列: [0, 1, 2]
- **步骤3**：弹出队首 1 → 遍历 1 的邻接表 [0, 3]。0 已访问跳过；3 未访问，访问 3 并入队。队列: [2, 3]，访问序列: [0, 1, 2, 3]
- **步骤4**：弹出队首 2 → 遍历 2 的邻接表 [0, 4]。0 已访问跳过；4 未访问，访问 4 并入队。队列: [3, 4]，访问序列: [0, 1, 2, 3, 4]
- **步骤5**：弹出队首 3 → 遍历 3 的邻接表 [1]。1 已访问跳过。队列: [4]，访问序列不变
- **步骤6**：弹出队首 4 → 遍历 4 的邻接表 [2]。2 已访问跳过。队列为空，BFS 结束。最终访问序列: 0, 1, 2, 3, 4。每个顶点距源点 0 的层数：0 在第 0 层，1 和 2 在第 1 层，3 和 4 在第 2 层，体现了 BFS 的分层特性

### 主动练习 1（输出预测）
- **类型**：output_predict
- **题目**：给定如下无向图和 DFS 递归代码，预测程序从顶点 0 开始遍历的输出序列
```
图结构（无向图）：
顶点: 0, 1, 2, 3, 4
邻接表（按升序排列邻接顶点）:
0: [1, 3]
1: [0, 2, 4]
2: [1, 3]
3: [0, 2, 4]
4: [1, 3]
```
```cpp
bool visited[5] = {false};
void dfs(int v) {
    visited[v] = true;
    cout << v << " ";
    for (int u : adj[v]) {
        if (!visited[u]) {
            dfs(u);
        }
    }
}
// 调用: dfs(0)
```
- **答案**：输出序列为 `0 1 2 3 4`
- **反馈**：从 0 出发，先访问 0 输出 0。遍历 0 的邻接表 [1,3]，1 未访问递归到 1 输出 1。1 的邻接表 [0,2,4]，0 已访问跳过，2 未访问递归到 2 输出 2。2 的邻接表 [1,3]，1 已访问跳过，3 未访问递归到 3 输出 3。3 的邻接表 [0,2,4]，0 和 2 已访问，4 未访问递归到 4 输出 4。4 的邻接表 [1,3] 均已访问，回溯结束。DFS 沿一条路径深入到底再回溯，与 BFS 的分层扩展不同，这体现了知识切片 cs101_k25 中"沿一条路径尽可能深地探索，遇到死胡同则回溯"的特性
- **来源**：数据结构与算法分析（Mark Allen Weiss）；知识切片 cs101_k25

### 主动练习 2（步骤排序）
- **类型**：step_order
- **题目**：以下是对有向图执行 BFS 遍历的通用步骤，请排列为正确的执行顺序
- **打乱步骤**：
  - A. 将起始顶点标记为已访问并入队
  - B. 取出队首顶点 v，遍历 v 的所有邻接顶点
  - C. 初始化 visited 数组全为 false，创建空队列
  - D. 对每个未访问的邻接顶点 u，标记已访问并将 u 入队
  - E. 检查队列是否为空，若非空回到取队首步骤
  - F. 队列为空时算法结束
- **正确顺序**：C → A → B → D → E → F
- **反馈**：BFS 的标准流程：先初始化标记数组和队列（C），将起点标记并入队（A）。然后循环执行：取队首顶点（B），遍历其邻接顶点将未访问者标记并入队（D），检查队列是否为空决定是否继续（E）。队列为空表示所有可达顶点已访问，算法结束（F）。这一流程体现了知识切片 cs101_k26 中"借助队列实现""先访问所有邻接顶点，再逐层向外扩展"的描述
- **来源**：数据结构与算法分析（Mark Allen Weiss）；知识切片 cs101_k26

### 现实案例
- **标题**：现实案例：导航软件的路线规划
- **正文**：导航软件从家到公司有多条路线，每条路有不同拥堵时间（边权）。Dijkstra 算法就像导航的核心逻辑：从家出发，每次选当前已知耗时最短的目的地扩展，用该目的地更新其邻居的预估时间（松弛操作），逐步确定到每个地点的最短时间。但如果某条路有"负时间"（比如经过会奖励时间），Dijkstra 的贪心假设就失效了——已确定的最短路径可能被负权边推翻，此时需改用 Bellman-Ford 算法。若要同时计算所有地点两两之间的最短路径（如全国公路网），Floyd 算法用三重循环一次性求解。

### 现实案例
- **标题**：现实案例：背包旅行与版本比对
- **正文**：背包旅行时，3 件装备各有不同重量和价值，背包容量有限，每件只能带或不带，如何在容量内让总价值最大？这就是 0-1 背包问题。暴力枚举所有组合是 2^n 种，装备一多就爆炸。DP 的思路是记录"前 i 件装备在容量 j 下的最大价值"这一状态表格，逐步从少到多填充，每个状态只需看"不选第 i 件"和"选第 i 件"两种决策取较大值，避免了重复计算。版本控制工具比对两段代码的差异时，找最长公共子序列（LCS）也是同样的思路：填一张二维表，逐步推导两段文本的最长公共部分。

### 逐步示例
- **标题**：0-1 背包问题的 DP 表填充过程
```
物品：
  物品1: w=1, v=15
  物品2: w=3, v=20
  物品3: w=4, v=30
背包容量 W=4
状态定义: dp[i][j] = 前 i 件物品在容量 j 下的最大价值
转移方程: dp[i][j] = max(dp[i-1][j], dp[i-1][j-w[i]] + v[i])  (当 j >= w[i])
```
- **步骤1**：初始化 → dp[0][j] = 0 (j=0..4)，dp[i][0] = 0 (i=0..3)，表示 0 件物品或 0 容量时价值为 0
- **步骤2**：处理物品1 (w=1, v=15) → j=1: max(dp[0][1], dp[0][0]+15)=max(0,15)=15；j=2: max(0,15)=15；j=3: 15；j=4: 15。dp[1] = [0, 15, 15, 15, 15]
- **步骤3**：处理物品2 (w=3, v=20) → j=1: max(15, 不选)=15 (j<w)；j=2: 15；j=3: max(15, dp[1][0]+20)=max(15,20)=20；j=4: max(15, dp[1][1]+20)=max(15,35)=35。dp[2] = [0, 15, 15, 20, 35]
- **步骤4**：处理物品3 (w=4, v=30) → j=1..3: j<w，同 dp[2]；j=4: max(35, dp[2][0]+30)=max(35,30)=35。dp[3] = [0, 15, 15, 20, 35]
- **步骤5**：读取结果 → dp[3][4]=35，即容量 4 下最大价值为 35。回溯决策：物品3 未选（dp[3][4]=dp[2][4]=35），物品2 已选（dp[2][4]=35 ≠ dp[1][4]=15），物品1 已选。最优方案为选物品1+物品2，总重 1+3=4，总价值 15+20=35

- **正文**：一天有多个活动候选，每个有开始和结束时间，一个人最多能参加多少个不冲突的活动？贪心策略是按结束时间排序，每次选结束最早且不与已选活动冲突的——这样给后面留出最多时间。这就像快递分拣站用分治法处理海量包裹：把包裹分成两堆各自分拣，再合并结果。贪心不回头，一旦选定就不撤销；分治则递归拆解再合并。0-1 背包不能用贪心（选了高价值物品可能占满容量错过更优组合），必须用 DP；但部分背包可以按单位价值贪心求解，因为物品可分割，贪心选择性质成立。

### 逐步示例
- **标题**：Kruskal 算法构建最小生成树的过程
```
连通无向图：
顶点: A, B, C, D
边（已按权值升序排列）:
  A-B (权1),  B-D (权2),  A-C (权3),  C-D (权4),  B-C (权5)
并查集初始: {A}, {B}, {C}, {D}
```
- **步骤1**：选 A-B(1) → A 和 B 不在同一集合，加入 MST。MST={A-B}，并查集合并：{A,B}, {C}, {D}
- **步骤2**：选 B-D(2) → B 和 D 不在同一集合，加入 MST。MST={A-B, B-D}，并查集合并：{A,B,D}, {C}
- **步骤3**：选 A-C(3) → A 和 C 不在同一集合，加入 MST。MST={A-B, B-D, A-C}，并查集合并：{A,B,C,D}
- **步骤4**：选 C-D(4) → C 和 D 已在同一集合 {A,B,C,D} 中，加入会形成环 A-C-D-B-A，跳过
- **步骤5**：选 B-C(5) → B 和 C 已在同一集合，加入会形成环，跳过
- **步骤6**：完成 → 已选 3 条边（n-1=3），MST 构建完成。总权值 = 1+2+3 = 6。Kruskal 的贪心策略是每次选最小权边且不构成环，借助并查集 O(α(n)) 判环，总复杂度 O(e log e)（排序主导）

### 主动练习 1（步骤排序）
- **类型**：step_order
- **题目**：以下是归并排序基于分治法的递归执行流程，请将步骤排列为正确顺序
- **打乱步骤**：
  - A. 递归对右半子数组执行归并排序
  - B. 合并两个已排序的子数组为一个完整有序数组
  - C. 检查子数组长度是否 <= 1，若是则直接返回（基准情形）
  - D. 将数组从中间对半划分为左子数组和右子数组
  - E. 递归对左半子数组执行归并排序
- **正确顺序**：C → D → E → A → B
- **反馈**：归并排序严格遵循分治三步骤（cs101_k43）：先判断基准情形避免无限递归（C），然后分解为两个子问题（D），递归解决左半（E）和右半（A），最后合并子问题的解（B）。这一流程体现了知识切片 cs101_k43 中"分解、解决、合并"三步骤。注意合并是归并排序的关键步骤，时间 O(n)，使得总递推 T(n)=2T(n/2)+O(n)，由主定理得 O(n log n)
- **来源**：数据结构与算法分析（Mark Allen Weiss）；知识切片 cs101_k43、cs101_k44

### 主动练习 2（输出预测）
- **类型**：output_predict
- **题目**：以下是贪心法求解活动选择问题的代码，活动已按结束时间升序排列。预测程序的输出
```cpp
// activities 已按结束时间升序排列
// activities = { {1,3}, {2,5}, {4,6}, {5,7}, {6,9} }
// 每个元素 {start, end}
int greedySelect(vector<pair<int,int>>& act) {
    int count = 1;              // 选第一个活动
    int lastEnd = act[0].second; // 记录已选活动的最晚结束时间
    for (int i = 1; i < act.size(); i++) {
        if (act[i].first >= lastEnd) {  // 不冲突
            count++;
            lastEnd = act[i].second;
        }
    }
    return count;
}
// 调用: greedySelect(activities)
```
- **答案**：输出 `3`
- **反馈**：贪心过程：选活动 {1,3}，lastEnd=3。活动 {2,5} 的 start=2 < 3 冲突跳过。活动 {4,6} 的 start=4 >= 3，选，lastEnd=6。活动 {5,7} 的 start=5 < 6 冲突跳过。活动 {6,9} 的 start=6 >= 6，选，lastEnd=9。共选 3 个活动：{1,3}, {4,6}, {6,9}。每次选结束最早的活动为后续留出最大空间，这是贪心选择性质的体现（cs101_k41）。注意活动选择问题有贪心选择性质所以贪心可得最优解，而 0-1 背包不具备此性质
- **来源**：算法导论（CLRS）；知识切片 cs101_k41

## Topic 8: 哈希表

### 知识切片引用
- cs101_k45: 哈希函数将任意长度的键映射到固定范围的哈希值（数组下标）。好的哈希函数应满足计算简单、分布均匀、对输入敏感...
- cs101_k46: 哈希冲突是不同键映射到相同下标的现象，冲突不可避免（鸽巢原理）。解决方法分链地址法和开放地址法...
- cs101_k47: 负载因子 α = 元素数 / 哈希表容量，衡量哈希表装满程度。链地址法 α 可大于 1，开放地址法 α 必须小于 1...
- cs101_k48: 哈希表在理想情况下查找、插入、删除平均 O(1)，最坏 O(n)。性能取决于哈希函数质量、冲突解决策略和负载因子...

### 现实案例
- **标题**：现实案例：图书馆的编号存取系统
- **正文**：图书馆用哈希表管理图书位置：通过书号计算一个存储位置（哈希函数 h(key)=key mod m），直接定位书架。如果两本书算到同一个位置（冲突），用拉链法就在该位置挂一个小书架（链表）存放多本；用开放地址法就找下一个空位放（线性探测）。负载因子就像书架装满程度：装太满找空位越来越难，探测序列越来越长，需要扩容搬到更大的书架并重新计算所有位置（rehash）。理想情况下放书取书都是 O(1)，但如果哈希函数差导致大量书挤到同一位置，找书就退化为逐本翻看 O(n)。

### 逐步示例
- **标题**：使用线性探测法解决哈希冲突的插入过程
```
哈希表容量 m=7
哈希函数: h(key) = key mod 7
初始状态: 空表 [_, _, _, _, _, _, _]
依次插入: 10, 24, 17
```
- **步骤1**：插入 10 → h(10)=10 mod 7=3，位置 3 为空，放入位置 3。表: [_, _, _, 10, _, _, _]
- **步骤2**：插入 24 → h(24)=24 mod 7=3，位置 3 已被 10 占据，线性探测下一位置 4，位置 4 为空，放入位置 4。表: [_, _, _, 10, 24, _, _]
- **步骤3**：插入 17 → h(17)=17 mod 7=3，位置 3 被 10 占据，探测位置 4 被 24 占据，探测位置 5 为空，放入位置 5。表: [_, _, _, 10, 24, 17, _]
- **步骤4**：观察聚集现象 → 三个关键字哈希值均为 3，连续占据位置 3、4、5，形成长度为 3 的聚集区。这是线性探测的主要缺陷（cs101_k46）：冲突元素堆积在一起，后续插入的探测路径越来越长
- **步骤5**：计算负载因子 → α = 元素数/容量 = 3/7 ≈ 0.43，低于阈值 0.7，无需扩容。若继续插入使 α 超过 0.7，需执行 rehash 分配 2 倍容量并重新哈希所有元素

### 主动练习 1（状态推演）
- **类型**：state_trace
- **题目**：给定如下使用线性探测法的哈希表（容量 m=7，h(key)=key mod 7），依次执行插入操作。请推演每次插入后的表状态
```
当前表状态:
索引:  0    1    2    3    4    5    6
值:   null null null  10   24   17  null

操作1: 插入 3
操作2: 插入 7
```
- **操作内容**：
  - 线性探测：冲突时从 h(key) 开始顺序向后探测 (idx+1) mod m，直到找到空位
  - 请给出每次操作后哈希表的状态
- **答案**：
  1. 插入 3：h(3)=3，位置 3 被 10 占据 → 探测 4 被 24 占据 → 探测 5 被 17 占据 → 探测 6 为空，放入位置 6。表: [null, null, null, 10, 24, 17, 3]
  2. 插入 7：h(7)=0，位置 0 为空，放入位置 0。表: [7, null, null, 10, 24, 17, 3]
  3. 最终表: [7, null, null, 10, 24, 17, 3]，负载因子 α = 5/7 ≈ 0.71，接近阈值
- **反馈**：插入 3 时需要探测 4 次才能找到空位（从位置 3 到位置 6），这正是聚集现象导致的性能下降。如果使用二次探测或双重哈希，探测序列不再是连续的，可缓解聚集。插入 7 哈希到位置 0 无冲突，直接放入。注意开放地址法要求 α < 1（cs101_k47），当前 α ≈ 0.71 尚可，但若再插入应考虑扩容 rehash

### 主动练习 2（输出预测）
- **类型**：output_predict
- **题目**：给定如下使用线性探测法的哈希表，预测查找函数对 search(17) 和 search(31) 的返回值
```
哈希表（线性探测，容量 m=7，h(key) = key mod 7）:
索引:  0    1    2    3    4    5    6
值:   null null null  10   24   17  null
```
```cpp
int search(int table[], int key) {
    int idx = key % 7;
    while (table[idx] != -1) {  // -1 表示空位
        if (table[idx] == key) return idx;
        idx = (idx + 1) % 7;
    }
    return -1;  // 未找到
}
// 调用1: search(table, 17)
// 调用2: search(table, 31)
```
- **答案**：search(17) 返回 5；search(31) 返回 -1
- **反馈**：search(17)：h(17)=3，table[3]=10 ≠ 17，探测到 table[4]=24 ≠ 17，探测到 table[5]=17 == 17，返回 5。查找路径与插入时的探测路径一致。search(31)：h(31)=3，table[3]=10 ≠ 31，table[4]=24 ≠ 31，table[5]=17 ≠ 31，table[6]=-1（空位），说明 31 不在表中，返回 -1。遇到空位即停止是正确的：线性探测插入时遇到空位就会放入，所以空位之后的元素不可能与当前键冲突。这也说明了开放地址法删除困难的原因——直接删除会留下空位打断查找链，需用软删除标记
- **来源**：数据结构与算法分析（Mark Allen Weiss）；知识切片 cs101_k46、cs101_k48

## Topic 9: 堆与优先队列

### 知识切片引用
- cs101_k49: 堆是一种满足堆序性质的完全二叉树：大顶堆中每个节点值不小于其子节点（父>=子），小顶堆则父<=子...
- cs101_k50: 堆化（heapify）是维护堆性质的核心操作。向上调整（sift up）和向下调整（sift down）...
- cs101_k51: 优先队列是支持插入元素和取出最高优先级元素的数据结构，通常用堆实现...
- cs101_k52: TopK 问题从 n 个元素中找出最大（或最小）的 k 个，是堆的经典应用...

### 现实案例
- **标题**：现实案例：医院急诊分诊与热搜榜单
- **正文**：医院急诊室用优先队列分诊：患者按病情严重程度而非到达顺序就诊，病情最重的优先。这就像一个大顶堆，堆顶永远是当前最紧急的患者。新患者来了插入堆中上浮到合适位置，处理完堆顶患者后取下一个最紧急的（堆顶弹出后下沉调整）。热搜榜单用 TopK 问题思路：每天数亿条搜索中实时找出最热的 k 个，用容量 k 的小顶堆——堆顶是当前第 k 热的，新搜索量超过堆顶就替换并下沉，最终堆中就是 Top-K。这比把所有搜索排序后取前 k 快得多，时间 O(n log k) 而非 O(n log n)，尤其是数据无法全部载入内存时优势显著。

### 逐步示例
- **标题**：从数组 [3, 1, 4, 1, 5, 9, 2] 建立大顶堆的过程
```
初始数组: [3, 1, 4, 1, 5, 9, 2]  (下标 0-6)
对应完全二叉树:
          3(0)
        /      \
      1(1)      4(2)
     /   \     /   \
   1(3) 5(4) 9(5)  2(6)

建堆方法: 从最后一个非叶节点 (下标2) 到根 (下标0) 逐个下沉调整
```
- **步骤1**：下沉节点 2（值 4）→ 左子 5（值 9）、右子 6（值 2）。9 是较大子节点且 9 > 4，交换 4 与 9。数组: [3, 1, 9, 1, 5, 4, 2]。节点 2 移至下标 5，为叶子，停止
- **步骤2**：下沉节点 1（值 1）→ 左子 3（值 1）、右子 4（值 5）。5 是较大子节点且 5 > 1，交换 1 与 5。数组: [3, 5, 9, 1, 1, 4, 2]。节点 1 移至下标 4，为叶子，停止
- **步骤3**：下沉节点 0（值 3）→ 左子 1（值 5）、右子 2（值 9）。9 是较大子节点且 9 > 3，交换 3 与 9。数组: [9, 5, 3, 1, 1, 4, 2]。节点 0 移至下标 2
- **步骤4**：继续下沉节点 2（值 3）→ 左子 5（值 4）、右子 6（值 2）。4 是较大子节点且 4 > 3，交换 3 与 4。数组: [9, 5, 4, 1, 1, 3, 2]。节点 2 移至下标 5，为叶子，停止
- **步骤5**：验证大顶堆 → 9 > 5,4 ✓；5 > 1,1 ✓；4 > 3,2 ✓。最终大顶堆: [9, 5, 4, 1, 1, 3, 2]。建堆总复杂度 O(n) 而非 O(n log n)，因为底层节点多但下沉距离短（cs101_k50）

### 主动练习 1（状态推演）
- **类型**：state_trace
- **题目**：给定如下大顶堆（数组表示），执行插入操作 7。请推演上浮过程并给出最终堆状态
```
当前大顶堆数组: [9, 5, 4, 1, 1, 3, 2]
对应完全二叉树:
          9
        /   \
       5     4
      / \   / \
     1   1 3   2
操作: 插入 7
```
- **操作内容**：
  - 插入 7 放在数组末尾，然后执行上浮（sift up）：与父节点比较，若大于父节点则交换，直到满足堆序或到达根
  - 父节点下标公式: parent(i) = (i-1) / 2
- **答案**：
  1. 7 放在末尾下标 7，数组: [9, 5, 4, 1, 1, 3, 2, 7]
  2. 上浮: parent(7) = (7-1)/2 = 3，arr[3]=1。7 > 1，交换 → [9, 5, 4, 7, 1, 3, 2, 1]
  3. 继续: parent(3) = (3-1)/2 = 1，arr[1]=5。7 > 5，交换 → [9, 7, 4, 5, 1, 3, 2, 1]
  4. 继续: parent(1) = (1-1)/2 = 0，arr[0]=9。7 < 9，停止
  5. 最终堆: [9, 7, 4, 5, 1, 3, 2, 1]
```
最终完全二叉树:
          9
        /   \
       7     4
      / \   / \
     5   1 3   2
    /
   1
```
- **反馈**：上浮操作从插入位置开始逐层与父节点比较交换，最多移动到根，路径长度为 O(log n)。7 从叶子层上浮两层到达节点 1 的位置（下标 1），因为 7 大于原父 5 但小于根 9。上浮和下沉是堆维护的两种基本操作（cs101_k50）：上浮用于插入，下沉用于删除堆顶。每次操作 O(log n) 保证优先队列的高效性
- **来源**：数据结构与算法分析（Mark Allen Weiss）；知识切片 cs101_k49、cs101_k50

### 主动练习 2（代码填空）
- **类型**：code_fill
- **题目**：以下是从 n 个元素中找出最大 k 个元素的 TopK 解法（使用小顶堆），请填写空缺部分
```cpp
#include <queue>
#include <vector>
using namespace std;

vector<int> topK(vector<int>& nums, int k) {
    // 小顶堆：堆顶是当前 k 个元素中的最小值
    priority_queue<int, vector<int>, greater<int>> minHeap;
    for (int num : nums) {
        if ((int)minHeap.size() < k) {
            minHeap.push(num);
        } else if (________) {  // 填空
            minHeap.pop();       // 弹出堆顶最小值
            minHeap.push(num);   // 插入新元素
        }
    }
    vector<int> result;
    while (!minHeap.empty()) {
        result.push_back(minHeap.top());
        minHeap.pop();
    }
    return result;
}
```
- **答案**：`num > minHeap.top()`
- **反馈**：TopK 问题用容量 k 的小顶堆：堆顶是当前 k 个元素中的最小值（第 k 大）。当新元素 num 大于堆顶时，说明堆顶不可能是 Top-K，弹出堆顶并插入 num；否则 num 不可能进入 Top-K，直接跳过。最终堆中 k 个元素即为最大的 k 个，时间 O(n log k) 远优于排序的 O(n log n)（cs101_k52）。注意此处用小顶堆而非大顶堆：求最大 k 个用小顶堆（堆顶是门槛），求最小 k 个用大顶堆，这是 TopK 问题的关键技巧
- **来源**：数据结构与算法分析（Mark Allen Weiss）；知识切片 cs101_k51、cs101_k52
